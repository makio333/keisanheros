# Web版と同じUI・ルールを使うUnity版 — 2026-10-19

## 標準起動の構成

標準シーンは `Assets/LegendHeroes/Scenes/LegendHeroesIdentical.unity`。
UnityのmacOSアプリ内にWKWebViewを配置し、現行Web版のHTML/CSS/JavaScript・画像・音声をそのまま同梱して実行する。
**全機能をC#に書き換えて同等化した、という方式ではない。** C#比較版は別シーンで残すが、標準アプリのルール・描画には使用しない。

この方式により、拠点の建物、冒険マップ、ステージ選択、入力、装備・合成、イベント、レイド、プリント、保存・管理画面はWeb版と同じ処理を使う。重複した画面・判定実装を標準にしない。

- Web版の元ソース・素材・ブラウザ保存は移動・削除・変更しない。
- `scripts/build-unity-web.mjs` が現行Web版をアプリ用に書き出す。16個のソースのSHA-256をマニフェストへ記録して照合する。
- Unityは読取専用のlocalhost配信と、WebKit表示、OSの印刷・ファイル選択・ダウンロードを担当する。
- 通常アプリの保存はWebKitの永続ストレージ。ブラウザ版や旧C#版とは独立する。共有セーブは元のゲーム内のセーブ選択を使用する。
- macOS以外のWebView実装はまだ追加していない。iOS/Android実機、署名・ストア課金を実装済みとは扱わない。

## UI一致のためのホスト側の調整

元のHTML/CSS/ゲームルールを改変せず、アプリ同梱時のみ以下を追加する。

1. PWAのService Worker登録を外す。アプリ自身が素材とバージョンを同梱するため、古いPWAキャッシュで更新が戻ることを防ぐ。
2. 既存の外部依存Chart.js 4.5.1を同梱する。グラフはオフラインでも表示し、MITライセンスを同梱する。
3. 元の事前読込が参照する旧 `画像/my_room.jpg` を現行の部屋画像へ対応させる。素材404を残さない。
4. macOS ChromeとWebKitの標準ボタン・CJKフォントの寸法差を `Native/webkit-chromium-compat.css` で補正する。主要10画面・72個の名前付きコントロールを同一画面サイズで比較し、位置・寸法を2 CSS px以内で照合する。文字のアンチエイリアス等、エンジン固有のピクセル差はあり得る。

5. 空のポップアップURLを標準のabout:blankへ正規化し、プリントの新規ウィンドウをアプリ内で開く。

## 保存・通信・検証の分離

- 通常Macアプリ：127.0.0.1:49317、永続WebKitデータ。
- Editorの通常プレビュー：49320、永続データ。
- Editorの隔離試験：49318、非永続WebKitデータ、Firebase実装を除いた専用パッケージ。
- 検証フックや仮のプレイヤーは製品パッケージに含めない。製品同梱JSをスキャンして検証する。
- 配信はループバックのみ。Host検証、パストラバーサル拒否、GET/HEADのみ、音声用Range対応。保存や任意コード実行のHTTP APIはない。
- テストは本番ランキング・実プレイヤーの共有セーブに書き込まない。
- QAの印刷はプレビュー内容だけを確認し、OSの印刷ダイアログや印刷ジョブを生成しない。通常アプリの印刷はOS標準シートで実行する。10問とプレイヤー名が実際の印刷ホストへ渡ることを確認。
- 終了時は元のpagehide/CloudSave.flushを呼び、1秒の猶予を取って閉じる。
- 開発ビルドは起動時のURL・画面・読込完了・エラーをアプリ自身の診断ファイルへ記録する。プレイヤー情報や任意実行用のネットワークAPIは含めない。

## 確認

- 元のWebルール：26テスト成功。
- パッケージ：16個の元ソースのハッシュ一致、検証フック非同梱、画像・音声・Chart同梱を確認。
- C#ホスト：Runtime/Editor/Playerの3種コンパイル成功。
- ローカル配信：27項目（Range、Unicode、HEAD、Host制限、パス制限など）成功。
- 実Unity/WebKit：23画面・34項目の表示・操作確認。購入キャンセル、種のゲーム内演出、Web形式の保存を含む。
- WebとUnityの配置比較：主要10画面の72コントロール。比較中だけアニメーションを停止し、恒久の表示設定へは入れない。
- 起動時の画像・音声リクエストは404なし。既存develop-web-gameクライアントでも起動とスクリーンショットを確認。
- Mac単独アプリの最終ビルド成功（857,931,835bytes、エラー0）。同プロジェクト `Builds/macOS/build-report.json` を参照。
- 単独アプリも起動し、HTTP200・素材100%・screen-title・JSエラーなしを独自の起動ID付き診断で確認。WebKitの起動画面画像を取得。
- ロック解除後、単独Macアプリで開始（キーボード）、新規登録画面への移動、名前欄への日本語設定・表示、入力の消去、タイトルへの復帰をCUAで確認。新規セーブ確定・本番クラウド書込は行っていない。座標クリックはCUAのnoWindowsAvailableにより使えず、ボタンはアクセシビリティ操作で確認した。
- 検証結果と代表画面は、Unity再起動で消えない `Documentation/LegendHeroes/Verification` に保管する。

## 更新手順

Web版の変更後は、Webルール試験 → 共通パッケージ生成 → ホスト生成 → Unity同期 → 実表示比較 → Macビルドの順に更新する。UIの差を別のC#画面で代用して解消済みとは扱わない。

C#比較版の過去の状態は `NATIVE_COMPARISON.md` に分離した。
